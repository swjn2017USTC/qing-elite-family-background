## 5. 失败项

**FAIL（门槛未过）**，两条独立原因：

1. **completion = 0%（四源口径，全部层）**：`sinica_lod` 对 120/120 人都是 `unavailable`。
   证据：`https://data.ascdc.tw/sparql.php` 对 GET/POST + `Accept: application/sparql-results+json` 一律返回 HTML 落地页（`data/interim/v03/sinica_probe.json`），平台自身只把 `/sparql.php` 作为页面链接；2026-09-15 未发现可机器查询的端点。
2. **D 层有效信息率 13.3% < 20%**：D 层 primary 实体多为 roster-only 人物（无 CBDB 链接），pilot 中 30 人只有 4 人获得 `explicit_id` 归属的命中；identity 命中 43.3% 全部来自**仅姓名**匹配（不计入有效信息，这正是 U00-03 的做法）。

次要但需记录：CBDB API 对"无记录"的名字返回 HTTP 404（首轮被误记为 `error`，已修正为 `not_found`），另有 2 次 SSL EOF 瞬时错误（已加重试）；CBDB API 返回无独立 endpoint 文档化的限速信息。

## 6. 影响研究结论的方法决策

1. **estimand 改为"文档率"**：primary estimand = P(documented ancestor office = 1 | tier)，分母是整层 frame，补集含 unknown —— 这是**记录率**，不是"祖先无官"的断言（`unknown != 0`）。次要 estimand = 在"祖先身份可考"子集上的条件率，必须同时报分母。
2. **只有 `explicit_id` 归属的命中计为有效信息**：仅姓名命中的 CBDB 记录在 pilot 中单列（D 层 9/30 属于此类），不进入信息率。
3. **协议 completion 双口径上报**：计划书口径（四源）与"可执行必需源"口径（cbdb_frozen / cbdb_api / wikisource_dump）；后者 A/B/C/D 均为 100%，说明协议本身可执行，唯一阻塞是 Sinica 接入。
4. **不改样本规模**（计划明令不扩样）；调整只能来自来源或 estimand。
5. 人工分钟数在 U03 **没有实测**（未做人工裁决），表里的 0.5 min/人 是假设值，已显式命名 `manual_minutes_per_person_assumed`，U05 必须实测。

### 调整方案（不改样本，供人工裁决）

针对失败 1（Sinica）：
- **A1**：U04 先按计划做条款/字段/限速核验，取得可机器查询的端点或合法导出；若平台确实只有 UI，则改用同为公开的 人名權威 数据导出（须先确认条款）。
- **A2**：若 U04 核验失败，把 `sinica_lod` 明确降级为 optional 源，completion 按必需源口径计算（pilot 实测 100%），并在 estimand 中写明该源当前贡献为零。
- **A3**：任何结论不得依赖该源，直到 A1/A2 落地。

针对失败 2（D 层有效信息率）：
- **B1**：D 层的主数量改为**可及性/记录率结果**（documentation rate + 上界），不参与 family-capital 的患病率对比；D 在 frame 的文档率为 0/400，本阶段已证明该对比退化。
- **B2**：若必须比较，则预注册一个"仅限有 accepted CBDB 链接"的 D 子框架（frame 内 302 人）作为**次要** estimand，明确其选择偏差。
- **B3**：为 D 增加其真正存在的属性来源（JSL 出身/籍贯已读；如权利允许，同年版《缙绅录》/题名录可提高 degree 可及性），但不得用其推断家世。
- **B4**：若三者都不接受，则 D 在 family-capital estimand 中列为 out of scope，并记录理由。

   D 层在 frame 内的文档率为 0，因此 D 只作为"可及性结果 + 上界"进入该 estimand；
   预注册**次要（tertiary）estimand**：D 限制在 `link_status = accepted_cross_link` 的子框架
