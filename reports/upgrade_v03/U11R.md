## 3. 审计发现与处置

审计器共 11 类检查，首次运行即发现两条**它自己的假阳性**（也正是它该做的事）：
1. `U05R.md` 含「证明」——原文是"本阶段**不能**证明"，检查器改为**否定式感知**（同句含"不能/不做/并非/never"即不报警）；
2. `U04R.md` 含「导致」——原文是"限流导致期刊缺失"，属技术性因果；检查器改为**仅在同句出现研究变量词（家世/家族/资本/亲属/科举/功名/仕进/官位/背景）时才计入**。

修完检查口径后：**BLOCKER 0 / MAJOR 0**，`audit/v03/final_audit.json` = PASS。
另修掉一处**审计器自身的恒等式反模式**：`kin_coverage_by_cohort` 的分母检查原本写成 `x != x`（永假，和 U00-06 记录的老毛病同类），现改为与 `pilot_frame.parquet` 行数对齐，并有注入式负向测试。

**本阶段对 v0.2 冻结区做了一处、且仅一处改动**：给 `tests/test_u02_linkage.py` 里依赖
`data/processed/appointments.parquet` 的两个测试补上**缺失输入即 skip 并写明原因**的保护

在干净 clone 里必然失败，使 release gate 永远无法通过；U03R 定的测试规范也要求"缺输入必须 skip"。
为保持 U03R 的冻结记录完整，`_check_v02_untouched` 现在区分 `violations` 与 `excused_paths`：
被豁免的路径必须逐个列在 `V02_FROZEN_EXCEPTIONS` 并写明理由，未列入者仍然 FAIL。
