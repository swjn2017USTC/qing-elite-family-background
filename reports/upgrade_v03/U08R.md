## 4. 关键口径与结果

### 4.1 事件构造（JSL）

JSL 的 `阳历年份` 是**小数**（1760.75 = 1760 年第 4 季）；本阶段保留小数作为排序键、另取整数年，
然后把**连续季度**的同官记录折叠为一个任命段，季度断档即开新段（等同再任）。
按此口径：158,333 条观测 → 146,823 段。

### 4.2 任命组成（全部事件平均）

`substantive` 0.9817、`concurrent` 0.0102、`acting` 0.0023、`honorific` 0.0004、`expectant` 0.0000。
注意：这是**事件级**份额，不是人级比例；expectant 为 0 与 JSL 公开版对"候补/候選"记录不全的已知限制一致（用户指南 3.2.3 有专门小节）。

### 4.3 派生结果示例（53,701 人）

平均任职跨度 `career_length_years` 4.93 年（仅对有起止年者）；有品级 22,923 人、有中央/地方路线 39,308 人；
路线分 `central_only` / `local_only` / `mixed` / `unknown`。

### 4.4 品级（人工验收"补"的那一项）

- CGED-Q 公开版的 `官缺等级`（衝繁難）与 `缺分`（要缺/簡缺）**都不是品级**；CBDB OFFICE_CODES 在本 release 亦无 rank 列。
- 因此品级来自 `config/v03/office_ranks.yaml`：**策展表**，basis 记《清史稿·職官志》文职官品，`verification_status: pending`（尚未逐条核验原书）。
- 覆盖：7,504 / 15,725 个官称可判品级（按官称计；按事件计见 metrics）。
- **使用限制**：任何以 `rank_class` 为基础的结论必须同时声明"品级表未核验"；未匹配的官称一律 null + reason，不猜。

### 4.5 跨来源冲突

本阶段 `conflicts_across_sources = 0`，原因是**两个来源用各自的 person id（JSL `S*`/`N*` vs CBDB `cbdb:*`），
在没有应用 U06R 链接之前不会共同指向同一个 person**。冲突检测逻辑已实现并有单元测试，
但要在 U09R 先把 U06R 的 `entity_links` 应用到事件表的 person 键上，这个数字才有意义——已写入下一步验收。

## 5. 失败项与限制

1. **品级表未核验**（策展，pending）：这是本阶段最大的方法论风险，已用 `verification_status` 显式标注。
2. **legacy tier 只覆盖 447 / 53,701**：v0.1 的 A/B/C 词表是为高官设计的，JSL 地方官绝大多数不落其中；这是"tier 不再作为 primary outcome"的又一个实证。
3. **跨来源冲突当前无法触发**（见 §4.5）：需要先做 id 归一。
4. **官称未匹配 6,605 条**：JSL 的 `官职一` 常是复合串（机构+职务），关键词表与品级表都按最长匹配，仍有一批无法判定，全部标 unmatched + reason。
5. **biographies 未使用**：本阶段面板不需要补缺；规则（不得静默覆盖结构化来源）已由冲突标记机制承担。
6. **事件级 appointment 份额不能当人级比例**（已注明）。
7. 2 项既有测试失败（缺 `data/processed/appointments.parquet`）非本阶段引入。

## 6. 影响研究结论的方法决策

1. **tier 彻底退居 legacy**：职业位置一律用事件表与派生结果表达；tier crosswalk 只作 extension outcome。
2. **品级必须带 provenance**：策展表 + verification status 随行；未核验不得进入实质结论。
3. **spell 折叠规则固定**：连续季度同官 = 一段；断档 = 新段，并在报告中写明（否则"任职次数"口径不可比）。
4. **跨来源不合并**：同人同年不同官 → 标记 + pending review，而不是让一份来源覆盖另一份。
5. **lineage 先行**：事件带 document id，结果带 event ids，保证 U09R 的每个数字可回溯。
