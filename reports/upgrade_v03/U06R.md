## 4. Coverage 与质量

- **gold 可达率**：cross_source gold 480/480 全部落在我的候选集内；dedupe gold 344 中 74.4% 可达 → **候选生成是 dedupe 评测的召回上限**，剩余缺口来自 v0.2 未文档化的变体字/折叠规则，已如实记录。
- **follow-up 修复（人工验收 1）**：Splink blocking/EM 规则改为带别名写法后 baseline 可运行，结果见 §5.1；**dedupe blocking（人工验收 5）**新增 `structural_key`（同 given_name + 同 core office + 同年）后，gold dedupe 可达率 **74.4% → 82.6%**；剩余 17.4% 只共享"名"（不同姓、不同官、不同年），v0.2 曾据此合并——这正是本项目拒绝的"仅凭姓名推断身份"，故**不加 given-name-only key**（代码中以默认关闭的 `block_given_name_only` 显式记录该决定）。
- **三套 matcher（held-out 88 对，25 正）**：ML @0.5 = precision 1.0 / recall 1.0；deterministic @0.5 = precision 0.373（314 次接受）；Splink 无分数（见 §5.1）。agreement：`det` 197、`det+ml` 117、`ml` 2、`none` 103 ——**197 对仅有规则支持**，这正是 deterministic 精度低的原因：规则在 alias/variant 场景里过于宽松。
- **auto-accept 区域**：ML 阈值 0.35 → precision 1.0、recall 1.0、覆盖 0.284（held-out 25 个阳性全部正确）。deterministic 无区域可接受 → 全部转 review。
- **abstention**：[0.3, 0.7] 灰带 3 对（3.4%），带内 precision 0.0 → 该带确实拦住了错配。
- **risk 分层**：MEDIUM 360 / LOW 59；**人工队列 102 条**（无固定比例抽样，且只路由 MEDIUM/HIGH）。
- **validator**：chronology 117 条（代理口径粗糙：用 CBDB index year 与 JSL 任期窗比较，缺年者不计）、geography 63、career transition 0。**未把 validator 命中当作错配证据**，只作为风险分量。

## 5. 失败项与限制（显式）

### 5.1 ~~Splink baseline 无法运行~~ → **已修（U06R follow-up）**

**根因（最小用例已复现，非数据问题）**：本仓库的 Splink 4.0.17 在 `block_on("name_norm")` 下生成的 blocking SQL 是
`ON (name_norm = name_norm)`，DuckDB 判定为歧义列（`Binder Error: Ambiguous reference`）；用两行合成帧即可复现，
因此不是重要样本或 dtype 的问题。**同一原因也影响 EM 训练规则**，而它失败时 Splink 只警告、不报错
（m 值不训练，回落到默认值）。

**修法**：blocking 规则与 EM 规则都写成带表别名的 `l.name_norm = r.name_norm`。

**修后结果**：EM 收敛（`em_converged: True`）；对 419 个交叉 gold 对中的 **353 对**给出分数
（84.25%，其余因 Splink 自身只用姓名 blocking 而未生成）；最大概率仅 **0.0228** → Splink 在 held-out 上
**没有任何达到 0.99 precision 的 auto-accept 区域**（best available: threshold 0.05、precision 0.0）。
即：v0.2 的 baseline 配置在本评测面上不具备自动接受能力，这与 U02 当年"概率路径贡献有限"的观察一致。

### 5.2 其他限制

1. **官方 id 本身不是权威身份**：用户指南明说是距离算法生成的连接变量；本阶段实测它只把 68.3% 的 gold dedupe 正例视为同一人，且 0.42% 的 gold 负例被并到同一 id → 官方 id 也不完美，**但它比我们的规则更可复现**，且带版本与文档。
2. **held-out 只有 88 对 / 25 正例**：ML 的 precision 1.0 落在小样本上，min_support=20 是防呆而非充分证据。
3. **拼音 blocking 带来大量新候选**（113,019 对），但评测面不含它们（gold 是 v0.2 抽样），因此**拼音 blocking 的收益未被度量**。
4. **stroke blocking 未实现**：上游依赖 CC BY-NC 词典 + 2.6 GB 笔画 n-gram 词向量，不 vendor；用字形代理替代。
5. **dedupe 任务只做审计**：官方 id 就位后内部去重不再是主要工程任务；本阶段只校验其一致性。
6. `record_number` 有 42 条重复，说明 release 自身存在少量重复行（未在本阶段清理，保留原样）。
7. 2 项既有测试失败（缺 `data/processed/appointments.parquet`）非本阶段引入。
8. **数据准备的一个连带修复**：下载 CGED-Q 后，`test_p03_family.py` 从 skip 变成运行并暴露真问题——上游 recode 表原格式是 **Stata .dta**（`?format=original`），默认访问给出的表格转换是 GBK 且列名乱码；已按 v0.1 manifest 的说明改为「下载原格式 + 本地转 UTF-8 TSV」，并把该转换写入 `manifest_v03.json`。

## 6. 影响研究结论的方法决策

1. **内部去重改用官方 id**：v0.2 的 dedupe（1,282 次合并 / 986 组）降级为 crosswalk 中的 audit comparison；任何后续统计以官方 id 为人员主键。
2. **auto-accept 只允许 ML 区域（阈值 0.35）**，deterministic 单独不能接受链接——与 v0.2 "unique_name 不是身份"同源，但这次给出量化证据（同 held-out 上 0.373 vs 1.0）。
3. **abstention 优先于扩大人工**：灰带与未达门槛的条目全部进 review，人工预算 300 条在 U06R 未消耗，留给 U07R/U08R 的真正疑难。
4. **validator 只作风险分量**：chronology/geography 命中不进结论，避免代理口径污染研究对象。
5. **不 vendor CC BY-NC 资产**：只借方法、不复制代码与二进制；上游 repo/commit/license 写入包元数据与 benchmark。
6. **legacy 冻结产物从 git 历史恢复**（`bd64fba`）而非重算：这是唯一能拿到 v0.2 gold 的途径，且不修改旧 artifact。
