## 2. OMP schema 与 provider / model ID（实测）

OMP 版本：`omp v18.1.13`（`/opt/homebrew/Cellar/omp/18.1.13`）。使用的命令：

```bash
omp config list --json
omp config get modelRoles
omp models opencode-go
omp models opencode-go --json
omp models find deepseek
```

确认的关键 schema：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `modelRoles` | record | 角色 → **model pattern 字符串**；可用 `:<level>` 后缀指定该角色的显式 thinking level |
| `defaultThinkingLevel` | enum | 可选 `minimal/low/medium/high/xhigh/max/auto` |
| `modelRoleStorage` | enum | `global`（默认）/ `project` |
| `advisor.enabled` | bool | 配对 advisor 模型 |
| `task.maxConcurrency` | number | subagent 并发上限（global 默认 32） |
| `task.agentModelOverrides` | record | agent 名 → **model pattern 字符串** |
| `task.agentAdvisor` | record | agent 名 → advisor 模型或 `"off"` |
| `task.enableEffort` | bool | 是否允许调用方按 spawn 覆盖 thinking level |

**实际 model ID（以 OMP 输出为准）**：`opencode-go/deepseek-v4.1-flash`

```text
provider=opencode-go  id=deepseek-v4.1-flash  context=1M  maxOutput=384K
thinking=[low, high, max]  images=yes
```

注意：该模型只声明 `low/high/max` 三档，**`low` 即其最低可用档**，不存在 `off/minimal`。

`opencode-go` provider 共 38 个模型（含 `deepseek-v4-flash`、`deepseek-v4-pro`、`glm-*`、`qwen*`、`kimi-*` 等），本阶段一个都不用；P00 只固定主模型。

- 配置层：`omp config get modelRoles` 显示全部角色带 `:low`；`omp bench opencode-go/deepseek-v4.1-flash:low --runs 1 --profile chat` 的输出把解析后的 selector 打印为 `opencode-go/deepseek-v4.1-flash:low`，证明后缀被角色/pattern 解析器接受。

## 8. 失败项

1. **项目级 `.omp/config.yml` 的 `modelRoles` 不接受对象形式**。`{model: ..., thinkingLevel: low}` 在项目文件里被静默丢弃（实测：`omp config get modelRoles` 回落 global 值）；global profile 中沿用旧对象形式（如 `commit`）是历史遗留。→ 采用字符串 + `:<level>` 后缀形式解决。
2. **`omp --model <provider>/<model>:<level>` 不可用**：CLI 报 `Model "..." not found`（该路径只在有 `enabledModels`/configured pattern 时接受后缀）。需要临时改档时用 `--thinking=<level>`，或在单个任务里改角色配置。
3. **thinking 档位未观测到实际效果**（见 §4），仅有配置层与解析层证据。
4. **未做 subagent 覆盖的运行时验证**：`task.agentModelOverrides` 仅验证到配置生效层（`omp config get` 与代码路径阅读），没有真的 spawn 一个 subagent 去核对它跑在 `:low` 上，以避免 P00 产生额外 agent 开销。

## 9. 影响研究结论的方法决策

- 正式研究 LLM 渠道与 OMP provider 严格分离（本地 Python + 官方 API）；OMP 内 `deepseek` provider 保留给偶发交互，**不参与正式数据生产**。
- `low` 是 `deepseek-v4.1-flash` 声明的最低档，因此"最低可工作 thinking level"= `low`；本项目不预设也不自动进入 `max`。
- 单任务升档需人工可见理由；`task.enableEffort=false` 从机制上禁止调用方给 subagent 升档。
- 代码包采用 `src/qing_elite/<子包>` 命名空间，子包与计划书 §12 的 `src/{acquire,cbdb,cgedq,linkage,family,llm,analysis,utils}` 一一对应；外层包名用于让 `uv run` / `pytest` / 安装后 import 无需 path hack（若按 §12 字面把 `acquire`、`utils` 等作为顶层包安装，会污染 site-packages）。这是对计划书目录树的**唯一结构性偏离**。
- 本阶段**不创建** `CODEBOOK.md` / `METHODS.md`：两者需要预注册的官阶分档阈值与最终统计口径，现在写只能是占位内容；计划由 P02（官阶分档预注册）与 P08（方法定稿）产出。
- `.omp/agents/` 目前为空（不放自定义 subagent），约束全部通过 `.omp/config.yml` 表达，避免新增需要维护的 agent 定义。
- Git 身份：仓库原先没有 `user.name/user.email`，本阶段只设置了**仓库级**身份 `wahrfreiheit <wahrfreiheit@localhost>`（未改 global）。如与你的习惯不符请告知，可在后续阶段前修改。
