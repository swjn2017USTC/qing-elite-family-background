## 5. 失败项 / 阻碍

1. **CBDB 官方站点对脚本化访问返回 HTTP 403**（`cbdb.hsites.harvard.edu` 与 `projects.iq.harvard.edu/cbdb` 均被 WAF 拦），User's Guide 实时下载同样 403 → 改用 CBDB 项目自述的 Hugging Face 渠道 + Internet Archive 快照 `20251104010037`。已在 manifest 记录。
2. **GitHub REST API 在本机出口 IP 被限流**（403 rate limited）→ 改用 `git ls-remote` 与 `raw.githubusercontent.com`。
3. **Dataverse 默认端点返回的是重新摄取版本**：`/api/access/datafile/3011|3012`（无参数）拿到的字节与其登记的 MD5 不符；必须 `?format=original`。已复测通过并在 manifest 标注。
4. **CBDB release 缺 `ETHNICITY_TRIBE_CODES` 表** → `c_ethnicity_code`（清代：NULL 154,996 / 0 56,457 / 1 23,628 / 131 1,711 / 169 1,034）**无法本地解码**，民族/旗籍判定暂时只能依赖八旗地址。
5. **`ctext.org` 不可用**：反爬拦截页明确声明会对抓取者间歇性返回污染数据；其 API 返回 `ERR_REQUIRES_AUTHENTICATION`。故《清史稿》改用维基文库。
6. **未做**：中研院两库的详情页批量字段抓取、CGED-Q pinyin 变量版本（id 3013）下载、任何统计/历史分析。

## 6. 影响研究结论的方法决策

1. **CBDB 不能独立支撑家世结论**：清代三代覆盖（父 5.4%/祖 1.8%/曾祖 0.5%）过低，P03 的家世指标必须按 `extraction_method` 分层（CBDB / 结构化文本 / LLM），并把 coverage 作为第一结果报告——这从源数据层面印证了计划书 §十一 的判断。
2. **旗籍只能用八旗地址，且必须承认大面积 unknown**：`unknown != 0`；不得把"无八旗地址"读成"非旗人汉人"。
3. **CGED-Q 的 person_id 不可无条件信任**：官方指南明确建议抽查；P02 需先做 person-level 去重规则 + 抽查方案，再谈链接率阈值。
4. **"一人一季多条"不等于重复**：1760–1798 有 4,500+ 组同人同季多行，混合了兼任、多职与重复记录，去重必须逐案判断。
5. **《清史稿》定位为快速补证源**：只用 API 取"目标人物 ±500–1000 汉字"窗口；文本质量 50%，不作唯一依据（与计划书 §6.5 一致）。
6. **中研院两库按需逐人查询**：A 层 100% 核验 + 关键冲突 + 关键 missing 时才查，单次请求、限速串行，不做遍历。
7. **原始库只读**：CBDB 的 views / `ADDRESSES` / 外键增强只能在 `data/interim/` 副本上生成。
8. **引用义务**：CGED-Q 需标注 release（2026-08-31，版本 24.0）、DOI `10.14711/dataset/E9GKRS` 与 RGC 致谢；CBDB 需标注 release `cbdb_20260912` 与 SHA256。
